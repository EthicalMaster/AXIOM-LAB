# ADR-013 — Bounded scientific computation before general extensibility

**Status:** Candidate (Phase 05A)

**Decision:** Keep simple, explicitly supported operations rather than executing user-submitted general code. Use SciPy for t distribution, normality, root finding and quadrature; NumPy/SymPy for bounded linear/polynomial computation; scikit-learn pipelines for ML. Preserve a modular monolith and local-first storage until measured demand justifies distribution.

**Alternatives:** Pure custom numerical algorithms (higher validation and maintenance burden), arbitrary Python/SymPy expression parsing (unacceptable security risk), general notebook/remote code execution (requires sandboxing and lifecycle control), immediate distributed workers and PostgreSQL (extra complexity before a real load profile).

**Trade-offs:** Fewer operations and bounded datasets; some analyses are unavailable. But method contracts are teachable, reproducible within documented limits, easier to independently test and safer than uncontrolled code execution. Public access is not approved without worker isolation, authentication, quotas and penetration/load reviews.

**Review trigger:** First public/multi-user deployment or evidence that bounded local workloads cannot meet requirements.
