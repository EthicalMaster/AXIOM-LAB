# ADR-010 — Minimal experiment persistence and observation-sequence charts

Status: Candidate (01D), pending user verification.

Purpose: every scientific execution needs an identifiable run, durable metadata, and truthful visual representation. Use SQLite `experiments` and `runs`, frozen JSON configuration and results, dataset fingerprint, algorithm/version and runtime metadata.

Alternative: deferred persistence would make saved experiments impossible in Phase 01; notebook-only storage is hard to query; full Celery/Redis task queue is premature.

Advantages: auditable, bounded, straightforward. Disadvantages: SQLite/local files cannot serve as a multi-instance, multi-user deployment without change; no authentication, retry/cancellation, concurrent jobs or full environment lockfile capture yet.

Chart decision: deterministic sampling from actual numeric observations, limited to 250 points. No interpolated numerical values or time-series claims. Future: richer Plotly charting when user workflows require interactions.
