# ADR-008 — Bounded, on-demand column profiling

**Status:** Proposed in Phase 01B; accept after developer's local tests.

## Problem

A dataset preview cannot tell the user whether a column contains numbers, dates, categories, missing observations or mixed representations. Treating all strings as numeric would silently corrupt identifiers. We need useful inspection without claiming statistical inference.

## Decision

Introduce `GET /api/v1/datasets/{id}/profile` and a pure Python column profiling service. Reopen only the stored immutable original after verifying its recorded size and SHA-256. Reuse Phase 01A validation to bound inputs and make a second streaming pass to accumulate per-column metadata.

- Nonblank observation patterns: numeric, true/false, strict ISO dates/datetimes, or text. Mixed patterns are reported, never automatically coerced.
- Leading-zero numeric-looking tokens remain text. Only empty or whitespace-only values count as missing; `NA` remains a literal observation.
- Track at most 1,000 distinct values per column, report exact-vs-lower-bound explicitly. Keep at most three truncated examples per column.
- No new persistence schema or third-party dependencies. No AI, numerical statistics, transformations or data cleaning.

## Alternatives considered

1. **Infer in browser:** faster for small previews, but only sees first rows and produces untrustworthy full-data counts. Rejected.
2. **Compute and store profiles at import:** fast readbacks, but changes import contract/storage and requires cache invalidation/version management. Deferred.
3. **Use Pandas dtype inference:** efficient for future advanced analysis, but type defaults can coerce identifiers and require policy on NA tokens. Deferred to 01C after explicit scientific decisions.
4. **On-demand separate service:** chosen for transparency, simple testing and no migrations.

## Disadvantages and operational limits

- Two read/parse passes per profile request cost CPU; acceptable only under current 5 MiB / 50k row / 150-column limits and local-user scope.
- Type guesses are not semantic declarations; identifiers, units and locales remain unknown.
- Distinct count beyond the cap is a lower bound, not a true cardinality.
- Large public deployments require profiling jobs/caching, rate limiting, per-user access controls and shared storage.
