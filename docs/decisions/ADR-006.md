# ADR-006: Restrict mathematical inputs and expensive execution

**Status:** Proposed for Phase 0 approval (implementation details may evolve).

## Context

User data and expressions are untrusted; some math parsers evaluate Python.

## Alternatives considered

Arbitrary execution; bounded controlled operations with restricted grammar.

## Decision

Allowlisted scientific functions, strict validation, bounded execution. Isolated workers when justified by workload.

## Rationale

Prevents inappropriate arbitrary computation and helps contain runaway jobs.

## Consequences / limits

Limits expressiveness; document supported operations and environment-specific protections.
